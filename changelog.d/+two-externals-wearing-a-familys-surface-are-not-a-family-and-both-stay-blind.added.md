bash's `regex` and scala's `scan_string_content` were handed over as php's shape
and are not seated. Both derivations are priced here so the next lane starts from
a measurement rather than from the resemblance.

**bash** genuinely is php's *surface*: `REGEX` / `REGEX_NO_SLASH` /
`REGEX_NO_SPACE`, three terminals from one function on `valid_symbols`. Per byte
it is a different animal. It keeps three independent depth counters (paren,
bracket, brace) plus an in-single-quote flag and stops on the first closer that
would go negative, where `marrow` walks to a delimiter its roster names — there
is no close here to name. And it refuses on the **matched text** rather than on
what follows: a run of only `[A-Za-z0-9$_-]` is a word, so
`found_non_alnumdollarunderdash` gates the return.

It is not a `Provision` either, and that is a correctness hole rather than an
inconvenience. A pattern can carry depth-1 nesting; it cannot say "a `$` not
followed by `(`", which the C refuses on purpose — `// do not parse a command
substitution` — so the grammar's own `command_substitution` can take it.
Approximating it eats a node we build none of, which the troupe contract calls
worse than silence.

Priced: bash's whole damage is **413 bytes**, and the handover's attribution was
wrong twice over. The board's `unexpected [ at 565` is not `_concat` and not the
`[[` of the test command — it is the `[` of `[0-9]` **inside** `^-?[0-9]+$`, so
the wall is in the regex rather than beside it. 413 bytes against elixir's 22,724
is why this went last and stayed undone.

**scala** is `marrow.Family` and needs two widenings, not one.
`scan_string_content(is_multiline, StringMode)` is one walk over a data table
exactly as latex's is, but `Mark.interpolates` is a bool where scala's mode is
three-valued, and its close **emits a terminal carrying content** where every
seated family emits a close of known width. Declined on a third thing neither
widening reaches: the scanner keeps an `indents` array, `last_column`, and
`last_indentation_size` across calls, and `marrow`'s walks are memoryless by
construction. Seating the strings would put a stateful scanner's string half on a
stateless mechanism and measure clean on a corpus file that never exercises the
difference — the failure `specimen/README.md` was built to stop. A separate lane
also has a 7× instability in the board's scala reading (1,278 / 1,938 / 9,087),
so no tail-row delta here could have been believed anyway.

`bash/regex-in-test-command.sh` ships as a **handover, not a falsifier**, and its
`.expect` says so on line one. It is 0/6 today and cannot fall further, which is
the second hole the php lane left open said out loud rather than discovered later:
this file cannot tell a break from a baseline. It joins `swift/raw-string.swift`
and `python/print-as-statement.py` as a red row naming a construct nobody has
seated, which is what those rows are for.
