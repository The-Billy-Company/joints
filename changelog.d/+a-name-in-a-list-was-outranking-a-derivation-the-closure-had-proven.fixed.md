`verdict()` in the owners closure tested `scanner` before `conflict`, so a
terminal that is **both** a declared external **and** inside its own state's
viability set came back `scanner`. The two are not the same kind of evidence.
`seen` is derived from this state's items, so a hit is positive proof the
grammar licenses the terminal *here*; `blind` is a name in a list and says
nothing about position. Letting the list win files a press defect the closure
has already proven as somebody else's C scanner - and under a lane that does
not run C, which is the worst address it could be sent to.

Viability is asked first now. Where both hold the row still says so
(`... (also a declared external - seating it may be the cheaper repair)`),
because seating the external is real work even when the reading exists; what
changed is which lane the row is addressed to.

One wall in the corpus is in that position and it took a widened external set
to expose it: swift `_implicit_semi in state 398`, 29 bytes, `scanner` to
`conflict`. Small, and pointing the opposite way to the externals fix landing
beside it - that one moved 495 bytes *into* `scanner`, this one moves 29 back
out. Net on the scanner column across both: zero walls.

The count is the point rather than the bytes. A taxonomy where two branches can
both match and the first one silently wins will mis-address every future case
in whichever direction the branches happen to be ordered, and nothing in the
output says a choice was made. It said nothing here for 170 walls.
