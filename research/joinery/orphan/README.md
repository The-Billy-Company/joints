# orphan — what a demoted extra is actually a measure of

`standing.py` scores 56,766 bytes of `orphan` over the thirty: documentation
comments standing as top-level roots instead of hanging off what they document.
Kotlin holds 19,705 of them, the largest single number on the board, and the
brief that opened this lane said kotlin's problem "isn't strings at all".

It is strings. All of it.

The short version: **`orphan` is a symptom of a felled stack, and a felled
stack is a symptom of a wall.** Kotlin's wall is its blind
`_string_start`/`string_content`/`_string_end` family, worth **20,728 bytes of
`built`** (41.4% → 99.3% standing on `Maps.kt`, +3.93 points of corpus
headline) — and the board's own work order, `unbound = rubble + spoil`, prices
the whole thing at **1,269 bytes** and ranks kotlin eighth. It does that
because `unbound` deliberately excludes `orphan`, and kotlin's orphan is not
measuring comment density; it is measuring how many times the stack went down.

No production file was edited. The seating is specified, costed, and declined
with a reason — the corpus holds zero triple quotes, zero `$` and zero escapes,
so nothing here could tell a sound kotlin fence from an unsound regex.

## The instruments

| Script | Question |
|---|---|
| `gate.py` | Over all thirty: mends against orphan bytes. Twelve grammars mend zero times, score zero orphan, and hand back exactly **one** root. |
| `ablate.py` | Length-preserving ablations of one source file, scored on `standing.ask`'s own row. Remove one construct class, keep every byte offset, and read what the mend count does. |
| `residual.py` | What is still walling an ablated file — the gaps no root covers, in context, plus `--mend=none` for the located first wall. |
| `walls.py` | Every orphaned row joined to the wall its parse stopped on. This is the work order `unbound` is not. |
| `shape.py` | One parse's top-level roots, so a large `built` can be checked for being a dishonest root stretched over a hole. |

All five read through `standing.py`'s own `ranged`/`tops`/`ask`, so none of them
can disagree with the board about what a root is. They want a binary:

```sh
OUTLINER_BIN=$PWD/.local/pin/<pin>/bin/outliner \
  python3 research/joinery/orphan/ablate.py
```

## The three numbers worth carrying out of here

- **php: one mend, one byte skipped, 8,091 orphan bytes and 119 roots.** The
  crown gate in `gather.zig` made visible in a single datum.
- **Blanking every comment in `Maps.kt` leaves `built` at 14,841 to the byte
  and the mend count at 142.** The comments carry nothing; they are the dye.
- **kotlin, php and scala are 31,842 orphan bytes behind three blind
  string-interior externals**, and `unbound` ranks them 8th, 10th and 15th.

## Both pages hold, and both under-priced themselves (2026-08-06)

Every number in this dossier is ours — `orphan`, `built`, `standing`, `unbound`,
mends — so nothing here asked whether the structure it counts is the structure
tree-sitter builds. Sighted, in `consort/RESULT-8-sighted.md`, and nothing
re-measured:

- **the mechanism holds, and holds hardest.** Kotlin, the subject of both pages,
  reads **35,324 `square` of 35,571 built — 98.6% `trued`**, so *a correct extra
  is an `orphan` and a misread one is `built`* was derived over a forest the
  oracle corroborates. That sentence is now the rule four other pages on this
  tree were overturned by (`consort/RESULT-10-record.md`).
- **php's datum is 8.3× the number above.** One mend does not cost 8,091 orphan
  bytes; seating the row it walls is worth **67,183 `square`** — the entire
  agreement php has with tree-sitter, 67,845 seated against 662 un-seated.
- **kotlin's wall is 31% more than the estimate.** `20,728 bytes of built` was
  explicitly a bet and not a measurement; the seating exists now and is worth
  **+27,143 `square`**.

The three orphan bytes carried out of here are all floors, in other words, and
the ranking `unbound` gave them — 8th, 10th, 15th — is worse than the page
already said.
